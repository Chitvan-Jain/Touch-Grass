# decision.md: what we decided and why

Newest decisions go at the bottom. Add a row whenever something changes.

| # | Decision | Why | Trade-off / revisit when |
|---|----------|-----|--------------------------|
| D1 | The app runs fully offline: everything lives on one laptop, phones connect over local Wi-Fi or a phone hotspot. | The challenge is about open models, and "works with no internet and no data leaving your machine" is the strongest story. | Players must be on the same network. |
| D2 | Model: `gemma4:e4b-it-q4_K_M` through Ollama. | Open-weight, multimodal (reads photos), and small enough for a 4 GB GPU with RAM spill. Also qualifies for Best Use of Gemma. | Slower than E2B. If judging takes too long, switch with `set MODEL=gemma4:e2b`. |
| D3 | Mobile-friendly web page instead of a native app. | Two-day deadline. Browsers can open the phone camera through a file input, which works over plain HTTP. | Cannot read real phone screen time. |
| D4 | Backend is Node.js + Express. | Smallest amount of code, one language end to end, easy to fix by pasting errors. | None for now. |
| D5 | Data is stored in one JSON file (`data.json`) held in memory. | SQLite needs native builds that often fail on Windows, and we only need a few hundred records. | Move to SQLite if the group grows or concurrent writes become a problem. |
| D6 | Photos are shrunk to 512 px in the browser and sent as base64 JSON. They are not saved. | Small images are judged much faster on 4 GB VRAM, and not storing photos supports the privacy story. | The feed shows captions, not pictures. |
| D7 | Gemma is both Quest Master and referee. Judge replies in JSON `{match, confidence, caption}`. A pass needs `match = true` and confidence of at least 60. | One model, two jobs, keeps the AI central to the product. A threshold reduces false passes from a small model. | Tune `MIN_CONFIDENCE` after testing about 15 photos. |
| D8 | If quest generation fails or returns junk, use a built-in list of 6 quests. | The game must never be blocked by the AI. | Fallback quests repeat sooner. |
| D9 | One scored completion per player per day. Identical photos (SHA-1 of the image) are rejected. | Cheap anti-cheat that needs no extra tooling. | A re-encoded copy of the same photo would pass. |
| D10 | (Replaced by D34.) Scoring: 10 points, +5 for being first in the group that day, plus streak bonus (streak days, capped at 5). | Rewards speed and consistency, which are the two things the game is about. | Adjust after playtesting. |
| D11 | No GPS verification. Multi-stop walks use numbered checkpoints (built, see D22). | Browsers block location on plain HTTP, and verifying distance is out of scope for two days. | Needs HTTPS or a native app. |
| D12 | Screen-time nudges use a number the player types in (built, see D20). | Web pages cannot read phone usage. A real version would use Android's usage-stats API. | Say this clearly in the write-up. |
| D13 | Mastra agent wrapper is deferred to layer 2. | Core loop (join, quest, photo, judge, leaderboard) must work first. | Only claim the Mastra category if we actually ship it. |
| D14 | No web fonts or CDN scripts. | Offline requirement. | Fonts are bundled in `public/fonts` (D29). |
| D15 | The judge prompt makes Gemma list the visible objects first, then decide, at temperature 0.2. Quest generation stays at 0.4. | A free-form "describe this photo" prompt misread a dorm room as a spa and invented activities. The structured prompt scored 10/10 on a 10-photo test (5 leaf photos, 5 lookalikes such as broccoli, kiwi and a game character). | The test used clean web-style images. Retest with phone photos, blur and close misses. |
| D16 | Confidence is shown only for passes. A fail says "Not quite" plus the caption. | Gemma reported 100% on photos it rejected, which read as a contradiction ("Not quite, 100% sure"). | The raw confidence is still saved in the feed log. |
| D17 | A batch test script (`test-judge.js`) is kept in the repo. | Gives a repeatable accuracy number for the write-up and lets us re-test after any prompt or model change. | It sends full-size photos, while the app shrinks to 512 px, so the app run is the final check. |
| D18 | Quests must be simple: no counting, no numbers, no rare items, no text or brands. The prompt says so, and generated quests containing digits or number words (or longer than 100 characters) are replaced by a fallback quest. | First phone test: Gemma invented "the brightest flower with exactly three visible petals". Nobody could finish it, and a small model cannot verify petal counts anyway. The judge correctly refused a white flower, but the quest was the problem. | Fallback quests repeat more often. Superlatives like "biggest" are still allowed. |
| D19 | Players can swap today's quest, but only while nobody in the group has completed it. | A bad quest should not block the whole group. Blocking swaps after a completion stops people from re-rolling for an easier quest once a friend has scored. | Anyone in the group can swap, since there are no roles yet. |
| D20 | (Detox is now a shared daily task, unlocked on the phone; see D31.) Screen time is typed in once a day. At 3 hours or more (`SCREEN_LIMIT`, default 3) the player gets a personal detox quest. | The web page cannot read phone usage (D12). 3 hours is a reasonable starting point that can be changed without code. | Honor system. A real version would read Android's usage stats. |
| D21 | Detox quests are personal, judged by the same Gemma judge, and worth a flat 15 points. They do not change the streak or the "first in group" bonus. One per player per day. | The group quest stays the main game, so detox cannot be used to farm streaks. 15 points makes it worth doing without outscoring the daily quest too easily. | Tune the reward after playtesting. |
| D22 | (Reveal rule replaced by D35.) Walk challenge: 5 checkpoints a day. Gemma writes 5 different simple targets (same rules as D18). Anything unusable is replaced from a pool of 12 built-in targets. Each player sees only the next stop, and finishing it reveals the following one. | This is the "5 photos on a 5 km walk" idea from the original concept. Revealing one stop at a time adds surprise and stops players from skipping to easy ones. Walk distance cannot be verified (D11), so a stop is a photo, not a measured kilometre. | The stop count is a constant (`WALK_STOPS`). Honor system on distance. |
| D23 | Walk scoring: 4 points per stop plus 10 for finishing all five (30 a day). It does not change the streak or the "first in group" bonus. | Keeps the three activities separate: daily quest drives streaks, detox is a nudge, the walk is the long goal. The completion bonus rewards finishing. | Maximum daily total is now high; tune after playtesting. |
| D24 | `public/index.html` was rewritten as one clean file. | A previous edit duplicated part of its script, which caused double polling. The duplicate was found while adding the walk UI. | None. Edits to this file are now made against the whole file, not by splicing sections. |
| D25 | Speed tuning after the first phone test: photos shrink to 512 px (was 640), the model stays loaded for 30 minutes (`keep_alive`), the page shows elapsed seconds while judging and allows one photo at a time. | Measured on the RTX 2050 (4 GB) with `gemma4:e4b-it-q4_K_M`: each AI task took up to about a minute. `ollama ps` showed 100% GPU, so CPU offload was ruled out (an earlier guess). The likely cause is Gemma 4's thinking mode (see D26). Smaller images mean less vision work, and showing the clock makes the wait feel intentional. | If it is still slow, switch to `gemma4:e2b` (`set MODEL=gemma4:e2b`) and compare accuracy with `test-judge.js`, which now prints seconds per photo. |
| D26 | Every Ollama request sends `think: false`. If Ollama answers 400 (it does not accept the flag), the request is repeated without it. | Even text-only quest generation took up to a minute, which points at Gemma 4 "thinking" before answering, not at hardware. Reports describe Ollama's gemma4 setup enabling it by default, and thinking adds nothing to a one-sentence photo verdict. | Not yet measured here. Compare timings before and after; if still slow, try `gemma4:e2b`. |
| D27 | The judge also reports `outdoors`. A photo that otherwise passes is rejected only when the model says `outdoors: false`. A missing field is treated as fine. Set `REQUIRE_OUTDOORS=0` to turn it off. | Phone tests showed walk and quest photos passing from inside a room, which defeats the "touch grass" theme. A lenient prompt and a reject-only-on-explicit-false rule limit wrongly refusing valid outdoor close-ups. | A small model may still misjudge. Measure with `test-judge.js` on indoor and outdoor photos. Screens and posters can still fool it. |
| D28 | The server sends one tiny request to Gemma when it starts. | After D26 the phone test measured about 4 to 5 seconds per photo, with one 28 second outlier that is most likely a cold model load. Warming up moves that cost to startup. | Only helps the text part of the model. If the first photo is still slower, it is the image side loading. |
| D29 | New look: teal, cream, coral, red and light blue; Barlow Condensed headings, Space Mono labels and buttons, Inter body; bordered cards with hard offset shadows; small pixel-block decorations. Fonts (open licence, SIL OFL) are copied into `public/fonts` and served by the app, no CDN. | The Hacktoberfest 2026 site was the style reference. It is a colour, type and layout mood, not a copy: our own wordmark and layout, none of their logo or artwork. Bundling the fonts keeps the offline promise (D1, D14). | About 120 KB of font files. Fonts load only after the first visit to the server, and fall back to system fonts if missing. |
| D30 | Game feel in the UI: stat tiles (points, 7-square streak meter, level with XP bar), a rank badge on each leaderboard row, a 5-square walk progress bar, reward panels on quest cards, and a pop or shake animation on pass or fail. Level is `floor(points / 50) + 1`, calculated in the browser. | Makes progress visible at a glance, which is what a competitive friends game needs. All of it is derived from data the server already sends, so there are no new endpoints. | Level is display only. Change the 50 in `renderStats` if levels come too fast or slow. Animations respect the device's reduced-motion setting. |
| D31 | Offline-first "sealed proofs". A photo is shrunk to 512 px and saved in the phone's `localStorage` queue first, then uploaded whenever a connection exists. Today's plan is cached on the phone, and a service worker (`sw.js`) caches the page and fonts so the app opens with no signal. The server stores each upload as `pending`, and the judge opens it later. | The goal is to be fully usable outside with no internet and reconnect at home. Judging after the fact is also natural because the judge (Gemma on a laptop) is at home. | `localStorage` holds about 5 MB (roughly 80 photos at this size). Service workers only run on secure origins (HTTPS, or `localhost`), so a plain `http://` laptop address gets no offline page caching. A hosted HTTPS deployment fixes that. A failed stop or quest cannot be retaken until you go outside again. |
| D32 | Two run modes. `MODE=local` (default): one process on the laptop serves the app and judges in-process. `MODE=hub`: a hosted copy with no AI. `worker.js` on the laptop makes outgoing requests to fetch pending photos, judge them with local Gemma and post verdicts. A shared secret (`WORKER_KEY`) protects the worker endpoints. | The deployed link needs a public server, but Gemma only runs on the 4 GB laptop. A mailbox plus home judge keeps the AI open-weight and local while the app is reachable from anywhere. The worker only makes outgoing calls, so no router or firewall setup is needed. | In hub mode photos pass through the hosted server (your own) and are deleted after judging (D37). Verdicts wait until the laptop worker is running. The page shows "waiting for the home judge" when it is not. |
| D33 | Quests come from a "quest bank" that Gemma fills ahead of time (squad activities, walk stops, detox tasks). Picking a quest removes it from the bank. If the bank is empty, built-in lists are used. Swap quest is a plain bank pick. | In hub mode the server has no AI, and offline phones need today's plan before they leave. It also removes the slow first load of the day and makes Swap instant. The D18 rules (no numbers, nothing rare) are applied when the bank is filled and again when it is stored. | Quests are not tailored to the day or weather. The bank is refilled only when the home judge is running. |
| D34 | The daily group quest is now a **squad quest**: an activity the whole group does together (ball game, walk-and-talk, frisbee, stretching). Each player sends their own photo. Gemma checks that people are visible, the activity fits and it is outdoors. Scoring: 10 + streak bonus (capped at 5). **Together bonus:** +10 to both players when a squadmate's passed photo was taken within 90 minutes of theirs. The "first in group" bonus is removed. | The point of the game is doing things with friends. Checking that two phones took photos near the same time needs no GPS, no extra taps and works offline. "First in group" cannot be calculated fairly when photos are judged in batches later. | The 90 minutes uses each phone's clock, so it can be cheated. A small model cannot count people, so it is only asked whether any are visible. |
| D35 | Walk stops are independent. Each of the 5 stops passes or fails on its own, and a failed stop can be retried. The phone reveals stops one at a time as you capture them (reveal is on the phone, not the server). 4 points per stop plus 10 when all 5 have passed. | With judging after the fact, a failed stop must not block the next ones. The server can no longer decide what to reveal because the phone is offline. | Players could peek at the full list in the network data. Not worth defending against here. |
| D36 | The phone decides what day it is and sends it (`YYYY-MM-DD`). The server accepts days within about 4 days of its own date. Streaks and daily plans use that day. | A hosted server runs in a different timezone, so its midnight is not the players' midnight. Proofs taken yesterday but uploaded today should still count for yesterday. | Wrong phone clocks are rejected only if they are far off. |
| D37 | Photos are kept only as temporary files until judged and are deleted right after. Only the verdict, a short caption and points are stored. | Keeps friends' photos off the server for as long as possible. Fits the "data stays with you" story and keeps `data.json` small. | The feed shows captions, not pictures. |
| D38 | Scope: this build includes the offline queue, the two modes and squad quests. The **do-it quest** (an activity a squadmate confirms) and the **photo duel** (groups of exactly 2, Gemma picks the better photo) come next because they sit on this pipeline. Bingo, sound hunt and the field journal were dropped. | Keeps each delivery testable. Bingo and sound hunt were not wanted. The journal needs typing and photo captions alone are too thin. | Do-it and duel are not built yet. |
